# Интерактивные результаты HASBoost

[Открыть файл HTML](../hasboost-results-interactive.html): скачайте его и откройте в современном браузере. Данные, графики и рисунок встроены в файл; сервер, CDN и новые расчёты моделей не нужны. Ссылки на GitHub требуют сети.

Верхний блок прежней инфографики сохранён. Пять разделов позволяют перейти от общего результата к конкретной модели:

- **Обзор:** метод, потолок памяти, группа наборов и метрика; междатасетное сравнение, диапазон трёх разбиений и матрица методов.
- **Датасет:** все сохранённые кандидаты, кривые заранее зафиксированного отбора, фактический размер, деревья, листья, ранг, поправки и эффект порогов. Есть сведения о поддержке меток и постоянные решения.
- **Парные сравнения:** произвольные A и B из семи семейств, тот же набор, разбиение и потолок. Показаны оба значения метрики, разница, фактические байты и идентификаторы. Отсутствие модели сохраняется.
- **Инференс:** сравнение legacy/packed для одной функции модели отдельно от сравнения разных обученных представлений. Доступны четыре батча и индивидуальные наборы.
- **Банк моделей:** память и задержка трёх банков при двух исполнителях и двух потоках запросов; вклад каждой из 12 моделей можно посмотреть отдельно.

Меню каждого графика или таблицы → **View data source** показывает исходные строки и определения. Кнопка **Скачать CSV** выгружает текущую таблицу целиком с действующими фильтрами, включая строки за пределами видимой страницы.

## Как читать сравнения

Кандидаты выбирались на D до теста. HTML не подбирает лучшую модель по тесту. Сравнение семейств при одном потолке не означает одинаковый фактический размер или одинаковую траекторию обучения.

Для F1 положительная разница — `100 × (A − B)`, в п.п.; для NLL и Brier — `B − A`. Сначала усредняются доступные разбиения набора, затем наборы получают равные веса. Отрезки — минимум и максимум трёх разбиений, которые используют общий тест; это не доверительные интервалы. Покрытие всегда видно. В диагностике постоянных решений знак иной и указан в заголовке: полная или обычная модель минус постоянное решение.

Новые наборы: Enron, CAL500, Corel5k и Delicious. Остальные восемь использовались при разработке, поэтому их результаты исследовательские. Порог меняет решения, но не вероятности. Ранг прямых моделей ограничен 64; проверены глубины 3/5 и до 200 деревьев.

Ускорение legacy/packed — медиана трёх парных отношений, затем медиана по наборам. Это не p95 общего потока. Для банка p95 измерен отдельно на 96 запросах; использовано первое разбиение каждой задачи. Пик своего пула CuPy уже включает массивы моделей. Предел физической вместимости A100 и преимущество относительно TabPFN здесь не проверялись.

## Источники и воспроизведение

`make_dashboard_snapshot.py` преобразует опубликованные CSV и `inference_pairs.json`, сохраняя числа и отсутствие значений. `app-metadata.json` фиксирует идентичность именно этого артефакта. `bank_choices.csv` добавляет 72 строки по шести ранее сохранённым B1-отчётам; происхождение и SHA исходников записаны в [provenance.json](../provenance.json).

Авторский код в `content/dashboard/` использует стандартные компоненты Data. Изображение берётся из `../figures/hasboost-results-infographic-v1.png`; повторно генерировать его не нужно. Защищённая среда Data в репозиторий не копируется.

Для сборки нужна установленная версия Data с API 1 и Node 20.19+ либо 22.12+. У проверенной сборки Node 24.19.0; SHA среды указан в `provenance.json` и [протоколе проверки](../checks/interactive-dashboard.json).

1. Создайте канонический проект Data через `data-app.mjs prepare --surface dashboard --project-dir <APP> --snapshot <SNAPSHOT>`. Снимок предварительно сформируйте командой ниже.
2. Скопируйте `content/dashboard/*` в `<APP>/src/content/dashboard/`; изображение — в `<APP>/src/content/assets/`. Сохраните полный снимок в `<APP>/src/data.json`. Остальные файлы среды не изменяются.
3. Запустите проверки и стандартную сборку. Для этой версии на Windows обнаружена ошибка проверки разделителей путей; проверенная сборка выполнена через WSL с теми же файлами и без ослабления проверок.

```sh
python make_dashboard_snapshot.py --evidence .. --metadata app-metadata.json --output <SNAPSHOT>
node --test <APP>/src/content/dashboard/analytics.test.mjs
node <DATA_PLUGIN>/output_formats/html/scripts/data-app.mjs build --project-dir <APP> --separate-data
node <DATA_PLUGIN>/output_formats/html/scripts/data-app.mjs export-html --project-dir <APP> --output <APP>/.data-app-offline/exports/hasboost-results-interactive.html
```

При воспроизведении этого файла используйте сохранённый идентификатор; для нового самостоятельного артефакта канонический подготовщик должен выдать новый. Команды приведены с параметрами путей, без локальных каталогов пользователя, ключей и обращений к серверу A100.

## Выполненные проверки

Восемь проверок сверяют состав данных, средние результаты, пропуски, знак разницы, фильтрацию, отношения времени и сумму памяти банка. В браузере проверены все пять разделов, переход к Birds, фильтр новых наборов и возврат ко всем данным, пустое состояние, NLL, раскрытие диагностик, исходные строки и выгрузка CSV. Верстка проверена при обычной ширине и при 390 пикселях; широкие таблицы прокручиваются внутри блока. Новые обучения и GPU-замеры при создании HTML не выполнялись.
