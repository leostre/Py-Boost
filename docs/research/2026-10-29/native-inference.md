# Сравнение с исходным инференсом Py-Boost

Дополнение от 30 октября 2026 года. В исходном репозитории рабочая ветка по умолчанию называется `master`, а не `main`. Ориентир зафиксирован на `b2842af472e21c7332d9487d8c83e53cb48d1486`.

На прежних сохранённых моделях измерены три исполнителя. Код `Ensemble.predict`, `Tree.predict`, CUDA-ядер и исходной функции BCE у ориентира не изменён. Модель восстановлена из сохранённых узлов и полных значений листьев в штатных структурах `Tree`, без обучения. Исходники проверяются по SHA-256. Загрузчик обходит только необязательные экспорты пакета и поиск версии установленного дистрибутива: в закреплённой среде пакет используется из исходников.

## Сравниваемые варианты

Для каждого набора измерены семь сочетаний:

- полная модель `ordinary/d3/t200` на исходном Py-Boost, legacy и packed;
- прежняя прямая AB-модель на legacy и packed;
- прежняя прямая AB + L модель на legacy и packed.

Во всех отношениях общий знаменатель — время полной модели на исходном Py-Boost. Для полной модели сравнивается исполнение одних деревьев и коэффициентов. Для AB/AB + L совмещены различия представления, траектории обучения и исполнения; разница качества выводится рядом. Исходный Py-Boost не исполняет AB + L напрямую.

## Измерение

Использованы 12 прежних многометочных наборов, первое сохранённое разбиение каждого, батчи 1/32/256/1024. На каждое сочетание — три сеанса по 32 запроса после четырёх прогревочных вызовов. Порядок исполнителей перемешивается. Конфигурации packed взяты из прежнего выбора на D; новой настройки нет. A100 была свободна: загрузка 0%, свободно 40 327 МиБ перед научным запуском. Число новых деревьев — ноль.

Полный запрос возвращает вероятности и метки: CPU → GPU → прогноз → прежние пороги → CPU. Обёртка исходного Py-Boost использует неизменённый `Ensemble.predict` с CuPy-входом, добавляет передачу данных и применение прежних порогов. Штатные выделения и синхронизация сохранены.

GPU-время — интервал CUDA-событий при уже размещённом входе, со всей цепочкой получения вероятностей и меток. В интервал входят паузы отправки ядер с CPU; это не изолированная сумма времени арифметики ядер. Основные буферы оптимизированных исполнителей подготовлены, штатные внутренние выделения Py-Boost сохранены. Отдельно нового пика памяти не измеряли.

Суммы и вероятности исходного Py-Boost — float32; legacy/packed — float64 при float32-параметрах и входах. Это часть практического сравнения штатных исполнителей, а не сравнение одинаковой арифметики. На D-префиксах до 37 объектов и дополнительном объекте с NaN прошли 336 проверок: максимум абсолютной ошибки вероятностей native `3.325457424152578e-7`, расхождений меток нет. Полная тестовая выборка для этой численной проверки повторно не использовалась.

## Результат

Медиана по 12 наборам при батче 1024:

| Модель | Py-Boost / legacy, p95 запроса | Py-Boost / packed, p95 запроса | Py-Boost / legacy, GPU p50 | Py-Boost / packed, GPU p50 |
|---|---:|---:|---:|---:|
| Полная, 200 деревьев | 3,50× | 3,58× | 27,98× | 40,15× |
| AB, 200 деревьев | 3,41× | 3,58× | 23,45× | 40,24× |
| AB + L, 200 деревьев | 3,43× | 3,55× | 22,68× | 35,07× |

По каждому набору сначала берётся медиана трёх парных отношений сеансов. Затем — медиана по наборам. Абсолютные p50/p95 в CSV вычислены по объединённым 96 запросам; отношение этих квантилей может отличаться от показанного ускорения.

Большое ускорение GPU-участка не превращается в такое же ускорение всего запроса: обмен CPU/GPU, выделения и получение результатов сохраняются. Результат сжатых моделей не доказывает дополнительного ускорения от сжатия — для этого нужно сравнение с полной моделью на том же оптимизированном исполнителе, сохранённое в дополнительных деталях HTML.

Код измерения опубликован в `research/external_controls/native_inference_study.py`, адаптер — в `native_pyboost_adapter.py`. Для восстановления оригинальных Python-файлов из уже имеющегося клона с нужным Git-коммитом:

```text
python research/external_controls/prepare_original_pyboost.py --repository .
```

Команда извлекает и проверяет исходники; она не устанавливает пакеты и не обращается к GPU. Для научного повтора дополнительно нужны прежние артефакты и закреплённая конфигурация. Модели, признаки и разметка не публикуются. Отчёты содержат только метаданные и времена запросов; качество перенесено из прежнего финального отчёта по точному `case/uid`.
