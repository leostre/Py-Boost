# Анимация полного пути инференса

Это учебные анимации, созданные по небольшому проверяемому ансамблю. Они показывают организацию вычислений, а не измеренную производительность.

Здесь многометочная классификация с независимыми сигмоидными выходами. Для многоклассовой задачи обработка выхода будет другой: softmax и выбор класса вместо независимых порогов.

## Что видно

1. На CPU поступает батч из двух объектов; параметры модели уже размещены на GPU.
2. Запрос проверяется и переводится в FP32. Признаки передаются на GPU.
3. Для каждого объекта выбираются листья. Цвета A/B обозначают разные объекты, а не классы или потоки CUDA.
4. Достигнутые значения накапливаются. В гибриде видны координаты Z и собранные поправки E; после декодирования получается вектор выходов.
5. Сигмоида даёт вероятности; порог определяет метки. Packed делает это внутри того же ядра, прежние пути — отдельно.
6. Вероятности и метки возвращаются на CPU. До этой передачи готового ответа на CPU на схеме нет.

У исходного Py-Boost поиск листьев и сбор значений разделены по деревьям. Legacy объединяет деревья блока; при широком выходе использует отдельное декодирование и суммирование. Packed обрабатывает блоки последовательно внутри одного CUDA-запуска: каждый блок имеет свои локальные суммы и, при необходимости, базис. Смена кадра внутри packed не обозначает новый запуск ядра. Показана схема прогретого запроса; компиляция и подготовка модели не включены.

## Математика учебного примера

Четыре бинарных дерева, два блока и два объекта. Узкий вариант использует C = 3, широкий — C = 144; отображаются первые три координаты. Для видимых координат:

$$
B=\begin{pmatrix}1&0&1\\0&1&-1\end{pmatrix},\qquad
b=(-0.2,\,0.1,\,-0.05).
$$

Исходные листья **заданы** как W = AB + L. Поэтому в этом учебном ансамбле полная и гибридная записи точно описывают одну функцию. Это не утверждение о точности реального сжатия исследовательских моделей: там W обычно лишь приближается через AB + L. В примере B одинаков для двух блоков, но анимация сохраняет отдельное накопление и декодирование каждого блока.

Независимая сумма полных листьев даёт оценки A = (0.6, 0.05, 1.0) и B = (−0.65, 1.0, −1.3). При температуре 1 и пороге 0,5 получаются метки A = (1, 1, 1), B = (0, 1, 0). Название объекта B не связано с матрицей базиса B. В реальном исполнителе исходный Py-Boost накапливает FP32, оптимизированные пути — FP64; учебный расчёт не эмулирует ошибки округления аппаратного ядра.

**Длительность GIF и темп HTML условны.** Они зависят от числа объясняющих этапов. По ним нельзя вычислять ускорение. Фактические времена остаются в прежних таблицах и не изменены этой редакцией.
