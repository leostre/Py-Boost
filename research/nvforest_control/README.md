# Изолированный контроль nvForest

Исходники финальной N2F сравнивают nvForest 26.10 и packed на одной и той же сохранённой полной модели с векторными листьями. Деревья не размножаются по выходам. Вероятности, метки и ограничение диапазона для nvForest объединены в отдельное CUDA-ядро: это усиливает контроль накладных расходов.

Каждое сочетание layout/chunk/батча проверяется численно до настройки скорости. Непрошедшие сочетания исключаются и сохраняются в отчёте. Отсутствие допустимого режима не заменяется выдуманным временем. Выбор скорости выполняется по D, финальные запросы используются для измерения.

`config.json` имеет `phase=publication`. Команда `python nvforest_runner.py` возвращает `publication_only` до проверки окружений, создания каталогов, установки пакетов или обращения к GPU. Исходная научная конфигурация и SHA сохранены как шаблон; её пути требуется восстановить отдельно. Прямой вызов измерительного модуля этот инертный вход не заменяет.

Собственная среда: Python 3.12.12, nvForest 26.10.0, CuPy 14.2.0, Treelite 4.7.0. Полный список закреплён в `requirements.lock.txt`; SHA-256 исходного описания среды — `0ae5c6745c736f2bb263b4f93b27b315b2f251c585af08a3945dd24254879561`. Среды HASBoost и TabPFN при проверках не менялись.

[Результаты и границы сравнения](../../docs/research/2026-10-30/README.md) · [документация nvForest](https://docs.nvidia.com/nvforest/26.10/python_api/). Итог не устанавливает универсального превосходства packed: при батче 1024 полный запрос почти равен, при 4096 сильный single-контроль быстрее по p95.
