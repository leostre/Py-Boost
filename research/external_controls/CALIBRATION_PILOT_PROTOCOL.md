# H-CAL1 — экономная калибровка сохранённых моделей

Утверждены только пункты 1–3 плана. Sol / xhigh, без подагентов. После отчёта — остановка. Переобучение деревьев, сжатие AB + L и новые данные запрещены в этой серии.

## Неизменные исходные условия

Пять прежних внешних разбиений: Helena 1204, MNIST 3104, RT-IoT2022 3204, WDBC 4104, Banknote 4204. Источник — проверенные прогнозы и модели H-QB1, запуск `9dd4f52c-7c03-4149-ba58-63b2401d792c`. Данные, внешний train/test, оба окружения, веса и сохранённый контекст TabPFN неизменны. Команда проекта остаётся `python3 -u external_runner.py`.

На каждой задаче используются 12 сохранённых PyBoost-моделей: глубины 3/5 × префиксы 40/80/160/200/400/800. Они нужны для проверки устойчивости выбора модели при бюджете. Отдельный фиксированный контроль — прежний TabPFN8. Итого 65 моделей, ноль новых обучений деревьев. Подробные кривые калибровки строятся для заранее выбранных d5-t200 и TabPFN8; их выбор не зависит от нового тестового качества. CatBoost/XGBoost и архивная глубина 4 остаются вне этого небольшого пилота.

Сохранённые прогнозы разработки используются напрямую. Недостающие тестовые прогнозы PyBoost разрешено получить только после фиксации всех выборов, на CPU и на неизменных моделях, с предварительным воспроизведением сохранённых прогнозов selection. Для TabPFN разрешены только сохранённые прогнозы: повторная подготовка контекста и инференс на GPU не нужны.

## Три схемы одного решения

Общая выборка разработки D объединяет прежние calibration, control, selection. Ни обучающие строки деревьев, ни тестовые строки в D не входят.

- A, `separate`: температура на calibration, смещения на control, выбор на selection.
- B, `pooled`: температура и смещения на объединении тех же выбранных объектов calibration/control, выбор на том же selection. Отдельные данные для двух преобразований не требуются.
- C, `crossfit`: D разделяется на три примерно стратифицированные части. Параметры выходов оцениваются на двух частях и проверяются на третьей. Прогнозы вне обучающей складки объединяются по объектам; macro-F1 считается на их объединении, не усредняется по складкам. После выбора политики параметры пересчитываются на доступной доле всей D. Деревья не переобучаются и не копируются по складкам.

Первый из десяти повторов A/B сохраняет исходные роли. Ещё девять переразбивают только D с теми же размерами ролей. Три складки C также меняются по заранее фиксированным семенам. Одинаковые разбиения применяются ко всем моделям; внутри повтора проверочные строки фиксированы для долей 25/50/100%. Подвыборки настройки вложены друг в друга.

Доли относятся к доступным строкам настройки каждой схемы. У A температура и смещения используют разные части; у B — одну общую; у C складки настройки и окончательного пересчёта имеют другие размеры. Это сравнение способов использования одной доступной D, а не причинное сравнение при одинаковом числе строк каждого вызова настройки. Фактические размеры, поддержка классов и число уникальных использованных меток сохраняются. Их нельзя скрывать за одинаковой подписью «100%».

## Настройка и выбор

Одна положительная температура в [0.1,10], сохраняемая как float32. Сохраняются прежняя функция вероятностей, ограничение вероятностей и NLL. В численном минимизаторе убрано вычисление неиспользуемого F1; результат проверяется относительно прежнего минимизатора.

Смещения: прежняя поклассовая эвристика по отступам, сетка 0, ±0.25, ±0.5, ±1, ±2. Доли смещения 0.25/0.5/1. Если в подвыборке нет положительных либо отрицательных объектов класса, его смещение равно нулю. Дополнительный порог поддержки 5/10 и поиск новой стратификации в пилот не добавляются. Поддержка каждого класса записывается, недостаток данных не маскируется.

Восемь различных политик: исходная; температура; три доли смещения без температуры; три с температурой. Исходный вариант всегда допустим. Для NLL выбирается только между исходной моделью и температурой: смещения не влияют на вероятности. Для macro-F1 доступны все восемь политик, с NLL как вторичным критерием. При точном равенстве предпочтительнее более простая политика. Вектор смещений и температура не поглощаются друг в друга.

Выбор политики для фиксированной модели и выбор PyBoost-модели по бюджету используют только проверочные оценки. Те же преобразования и сетки применяются к TabPFN. Сохраняются бюджеты B/B0: 0.25/0.5/0.75/1/1.5/2/4; B0 — прежние реальные массивы d5-t200. У PyBoost добавляются четыре байта температуры; уже имеющийся вектор смещений повторно не учитывается. TabPFN не получает выдуманный размер памяти «на одну задачу».

## Дополнительная проверка окончательного пересчёта C

Только для d5-t200 и TabPFN8 выбранная по тем же прогнозам вне складок политика дополнительно пересчитывается на числе строк, равном объединённой подвыборке настройки A/B. Это заранее заданная чувствительность к размеру окончательной настройки, а не четвёртый алгоритм отбора и не новая возможность выбрать победителя по тесту. Основной вариант C по-прежнему пересчитывается на доступной доле всей D.

## Фиксация и оценка

Все выборы для всех задач записываются и хешируются до первого обращения к тестовым прогнозам. Тестовые данные не входят в API математического ядра. После фиксации оцениваются заранее выбранные политики и варианты фиксированных моделей, а не лучшие на тесте точки. Выбор между схемами по отдельным датасетам на тесте не производится.

Основные результаты: NLL/Brier до и после температуры, разброс температуры, частота ухудшений, выбор исходной политики, macro-F1 после смещений, устойчивость выбранного ансамбля и занятой памяти. Результаты показываются отдельно по задачам. Для перекрёстного варианта приводится чувствительность к числу строк окончательной настройки.

Десять повторов описывают чувствительность к разделению D и настройке выходов, а не к повторному обучению моделей. Их нельзя выдавать за десять независимых датасетов, новых внешних разбиений или независимых подтверждений. Прежний тест уже использовался: выводы остаются исследовательскими. Перекрёстная оценка после выбора политики также не является несмещённой оценкой итогового качества.

## Решения реализации

- D-CAL-01: один дочерний узел сравнения схем после проверенной ветки H-QB1; исходные узлы не изменяются.
- D-CAL-02: достаточно поддержки 1 положительный/1 отрицательный объект для сохранения прежней эвристики; строгую защиту редких классов сейчас не подбираем.
- D-CAL-03: 12 PyBoost-моделей на задачу позволяют измерить устойчивость бюджетного выбора, не расширяя сетку новыми обучениями.
- D-CAL-04: фиксированные модели для подробного разбора — d5-t200 и TabPFN8, без отбора по новому тесту.
- D-CAL-05: дополнительный пересчёт C при сопоставимом числе строк отделяет эффект финальной выборки от механизма отбора.
- D-CAL-06: GPU не используется. Окружения не изменяются. Hypothesis применяется локально, где уже установлен; на сервере обязательны детерминированные проверки и независимые численные эталоны, без установки пакетов.

## Условия завершения

Должны пройти проверки разбиений, вложенности подвыборок, отсутствия утечки, численного совпадения температуры, неизменности argmax при температуре, независимости вероятностей от смещений, единой области классов, границ памяти и запрета теста до фиксации. После полного отчёта и проверки артефактов остановиться для обсуждения, не переходить к AB + L.
