# H-ABL-H1: история для новых приращений с защищённой старой функцией

Условный этап 6. Развилка H1-01 после T1/T2: прежний совместный регулятор не получил устойчивого общего подтверждения. Вместо его безусловного масштабирования выполняется ограниченная проверка механизма: может ли история помочь **новому приращению**, если уже накопленные базисы не перекодируются. Это отдельная исследовательская ветка, а не объявление прежнего регулятора готовым. Параллельное усреднение ветвей без нового контроля масштаба шага не повторяется.

Данные: прежние Yeast 1304/1314/1324, MediaMill 1104/1114/1124 и MNIST 3104/3114/3124. Точные роли из absolute_roles_manifest сохраняются. Это девять разбиений трёх задач; test повторно используется и считается исследовательским. Новые UCI-задачи этого этапа не используются для подбора метода истории.

## Проверяемый механизм

Представление после шага k:

$$F_k(x)=b_k+\sum_{u=0}^{k} f_u(x),\qquad f_u(x)=S_u(x)A_uB_u^\top+S_u(x)L_u.$$

Уже принятые блоки u<k сохраняют деревья, координаты, базисы и остатки. Проецируется только новый блок. Смещение нового блока добавляется к общему смещению; погрешность округления float32 учитывается при проверке реального прогноза. Хеши прежних блоков не меняются. Все отдельные декодеры оплачиваются; это несколько базисов, а не бесплатное расширение одного общего базиса.

Сравниваются пять траекторий одной конфигурации:

1. Полный контроль без проекции новых приращений.
2. Функциональный базис нового приращения по его прогнозам на train.
3. Базис текущего нормированного сигнала G/H.
4. Базис экспоненциального среднего того же сигнала.
5. Базис экспоненциального среднего матриц Грама сигналов.

Используются прежние диагональные производные и сигнал Z=−G/sqrt(H+lambda/n), после нормирования матрицы по Фробениусу. В многоклассовом случае удаляется общий сдвиг выходов. beta=0,8. История не меняет оси объектов и выходов. GaLore здесь является источником принципа проекции сигнала; алгоритм оптимизации нейросетей целиком не переносится и не объявляется реализованным.

Каждая задача начинает с одного полного блока 40 деревьев, общего для пяти режимов. Начальное смещение — ноль для softmax и прежняя логарифмическая вероятность класса для sigmoid. История наблюдает начальное состояние и реальные префиксы 10/20/30/40 этого блока. Затем до четырёх новых блоков по 40 деревьев. Следующее приращение обучается по фактической функции защищённых блоков, а не по отдельному полному учителю. Исходный ранг каждой новой компактной части — floor(C'/2), минимум 1; C'=C−1 для softmax и C'=C для sigmoid.

Глубина 3 и поддержка листа 10 одинаковы у всех пяти траекторий; lr=0,1, lambda_l2=1. Это устраняет смешение эффекта истории с изменением глубины, замеченное в T1. После проекции сравниваются остатки 0/1/2/5% от счётчика коэффициентов нового полного приращения. Один balanced_mse, margin_scale=0,5. В локальном контроле оценивается **сумма старой функции и нового приращения**, а не качество приращения как самостоятельного классификатора. Кандидат должен пройти прежний совместный допуск 5%; среди допустимых выбирается меньшая взвешенная обучающая ошибка восстановления, затем F1/NLL/память. При отсутствии кандидата сохраняется предыдущий снимок и прекращается эта траектория.

## Бюджет и честные затраты

Полный контроль до 200 деревьев обучается первым. Общая цена для четырёх компактных режимов равна floor(0,75 × цена его конечного представления без T)+4. Это нормировка относительно реально построенного контроля без использования test, а не онлайн-предсказание неизвестной будущей сложности. Контрольное обучение оплачивается в общем журнале. Все компактные режимы получают один и тот же предел; бюджет не вычисляется из их достигнутого качества.

Считается максимум двух реальных вариантов: упакованные COO-блоки с общим нулевым вектором и набор отдельно подготовленных CSR-блоков с их собственными копиями векторов. Это консервативная цена развёртывания; она не является пиком процесса. Дополнительно сохраняются память среднего N×C либо Грама C×C, диагностические половины Грама, предыдущий базис, время наблюдения и проекции, GPU-пул и RSS обучения. Полные временные G/H сохраняются; обучения только r коэффициентов этим этапом не заявляется.

Отдельное ускоренное CUDA-ядро для нескольких разных базисов не входит в этот этап. CPU-предиктор служит эталоном корректности. Скорость прежнего единого ядра с одним базисом на новое представление автоматически не переносится.

## Объём, выбор и проверка

Технический пилот: первые разбиения трёх задач, по пять траекторий с одним общим начальным блоком. Максимум 2520 новых деревьев; фазовый предел 2700. После независимого аудита начальных состояний, неизменности старых блоков, реальных цен и метрик автономно добавляются остальные шесть случаев, без повторного обучения пилота.

Полный максимум — девять × (40 общего начального блока + пять × 160 продолжения) = 7560 новых деревьев, жёсткий общий предел 8000. Отвергнутые блоки тоже оплачиваются; резерв 40 записывается до fit. Один собственный GPU-процесс одновременно. Чужие процессы не останавливаются; минимум 8 ГиБ свободной памяти, свой пул до 16 ГиБ, CPU до 32 ГиБ.

Окончательная схема B: общая настройка на calibration/control, выбор снимка и политики на прежнем selection. Для softmax — исходные выходы и температура со смещениями; для sigmoid — исходные выходы и пороги с T=1. NLL и macro-F1 выбираются отдельно. Обычный префикс в том же бюджете и полный контроль без ограничения остаются альтернативами. Численная нечувствительность 1e-6 / 1e-12 прежняя.

Все девять случаев и решения запечатываются после независимого аудита разработки до теста. Отдельный дочерний узел оценивает неизменный test без обучения. Основные сравнения — история против функционального, текущего и среднего базиса при одинаковом верхнем пределе памяти; 500 парных повторов строк для настроенных выходов и цели macro-F1. Ранний выбранный снимок без сжатого приращения не считается подтверждением истории. Три seed показываются по отдельности; «история полезна в среднем» не заменяет границы применимости по задачам.

По окончании фиксируется судьба дальнейшего объединения ветвей. Без устойчивой пользы базового представления и контроля масштаба шага оно остаётся условным продолжением, а не поводом повторять прежний отрицательный опыт или увеличивать число GPU-процессов.
