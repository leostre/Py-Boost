# H-LR4: выбор разреженного остатка без тестовой разметки

Дата фиксации: 2026-10-15. Родитель — завершённый H-LR1, запуск `7244bd7d-883e-4ef2-904c-e20123bd422a`, код `5b71ee0040f2fcb2b63165a79673c7de01cd59f3`.

## Границы

Используются сохранённые деревья, разбиения и обучающий функциональный базис для MediaMill, Helena и Yeast: по пять исходных разбиений. Деревья не переобучаются, GPU не используется. Среда и команда запуска прежние. Шестьдесят входных файлов закреплены по SHA-256 в `sparse_source_manifest.json`, исходные данные — прежним манифестом.

Тестовые ответы не передаются функциям выбора. Однако эти тестовые выборки уже рассматривались в предыдущей диагностике. Поэтому результат разведочный, а не независимое подтверждение. Новые разбиения и обучение новых деревьев в этот этап не входят.

Название узла содержит `label-free` в смысле **без тестовой разметки**, а не «без любых меток»: два правила используют обучающую разметку для балансировки.

## Представление и стоимость

Значения листьев представлены как $V\approx AB^\top+S$, где $S$ содержит выбранные остаточные коэффициенты, округлённые до float32. Для softmax остаток рассчитывается после исключения общего направления логитов. Средний вклад $S$ на обучающей выборке вычитается через уже существующее смещение; обновлённое смещение сохраняется в float32.

Число коэффициентов — $Mr+Cr+C+s$. Постоянно хранимые массивы включают деревья, смещения деревьев, $A$, $B$, смещение предсказания и остаток COO: float32-значение, int32-индекс листа, int32-индекс выхода. Один ненулевой элемент требует 12 байт. Для чисто малоранговой модели $s=0$.

Бюджет памяти означает сумму `nbytes` постоянно хранимых массивов модели. Накладные расходы Python, заголовки NPZ и временные рабочие массивы предсказания не входят в этот бюджет. Реальный размер файла измеряется отдельно. Извлечение CSR из COO — временная рабочая память, а не сохраняемая часть модели. Экономия памяти обучения и ускорение предсказания не заявляются.

Исходная стоимость Helena рассчитывается по точному представлению с одним неявным опорным классом, а не по избыточному общему направлению softmax.

Три режима общего ограничения:

- `parameters`: лимит числа коэффициентов; память измеряется, но не ограничивается.
- `memory`: лимит объёма массивов модели; коэффициенты измеряются, но не ограничиваются.
- `joint`: оба лимита одновременно.

В каждом режиме доля лимита равна 0,50, 0,65 или 0,75 от соответствующей исходной стоимости. Сравниваются **одинаковые верхние пределы**, а не искусственно выровненные фактические затраты. Из-за целочисленных рангов и числа элементов точное равенство обычно невозможно; неиспользованный бюджет не заполняется фиктивными параметрами. Фактические затраты публикуются.

## Три заранее заданных правила

Остаток $R=V-AB^\top$ выбирается сразу среди всех выходов, без предварительного отбора по тестовому или валидационному F1.

1. `energy`: $R_{mj}^2 p_m$, где $p_m$ — доля обучающих объектов, посещающих лист. Это простой контроль без балансировки.
2. `balanced_mse`: положительным и отрицательным обучающим примерам каждого выхода отводится одинаковая суммарная масса; если одна группа отсутствует, используется имеющаяся. Координаты ранжируются по положительному уменьшению взвешенной квадратичной ошибки логитов при добавлении одного полного остаточного коэффициента.
3. `balanced_margin`: та же оценка, но вес дополнительно умножается на $(\tau/(\tau+|\mathrm{margin}_{ij}|))^2$, $\tau=0,5$, затем нормируется по выходу. В multilabel граница — нулевой логит; в multiclass — разность логита выхода и максимального логита конкурента. Маржа рассчитывается по исходной модели только на обучающих объектах.

При $\phi_m$ — индикаторе посещения листа, $u_m=\phi_m-p_m$, $e=z_{\mathrm{teacher}}-z_{\mathrm{base}}$:

$$
\mathrm{score}_{mj}=\max\left(0,\;2R_{mj}\sum_i w_{ij}u_{im}e_{ij}-R_{mj}^2\sum_i w_{ij}u_{im}^2\right).
$$

Это точная оценка для одной координаты в соответствующей квадратичной цели, но не гарантия аддитивного улучшения набора координат или F1. Ранжирование статическое; равенства разрешаются по индексу. Нулевые остатки и неположительные оценки не выбираются.

## Сетка и выбор модели

Чисто малоранговый контроль рассматривает все ранги, проходящие хотя бы один лимит. Для построения остатков берётся объединение рангов $\max(1,\lfloor f r_{\max}\rfloor)$ при $f\in\{0,5;0,75;0,9\}$ по всем девяти ограничениям. Для каждого такого ранга проверяются размеры 25%, 50% и 100% доступной ёмкости остатка по соответствующим ограничениям. При выборе под конкретный лимит доступны все подготовленные варианты, укладывающиеся в него.

Каждое семейство с остатком также имеет все допустимые варианты без остатка. В обоих случаях выбор одинаков: максимальный валидационный macro-F1 среди прошедших три ограничения качества относительно исходной модели. Ограничения: функция потерь не хуже 1,05, macro-F1 и weighted-F1 не ниже 0,95 от исходных. Равенства разрешаются меньшей функцией потерь, меньшим объёмом массивов, меньшим числом коэффициентов, идентификатором. Если ни один вариант не прошёл ограничения качества, используется тот же порядок выбора среди допустимых по бюджету с явным признаком неуспеха.

Чисто малоранговый контроль не принуждается брать максимальный ранг: он получает возможность выбрать любой лучший ранг по валидации. Это более сильный контроль для проверки полезности остатка.

## Разделение выбора и теста

1. Для всех 15 разбиений рассчитываются только обучающие оценки и валидационные метрики.
2. Выбранные модели экспортируются без исходного плотного массива. Проверяется воспроизведение валидационных предсказаний после загрузки и точная стоимость массивов.
3. Решения всех разбиений записываются в единый `selection_manifest.json`, фиксируется SHA-256. До этого момента тестовые метрики новых вариантов не считаются.
4. Только после фиксации всех решений загружаются выбранные модели и рассчитываются тестовые метрики. Перед каждым разбиением проверяются неизменность манифеста и SHA-256 моделей.
5. Нет перебора кандидатов по тесту, изменения правил после просмотра первых тестовых результатов или продолжения на удачном варианте в рамках этого узла.

## Основное сравнение и интерпретация

Основное заранее выбранное сравнение — `balanced_margin` против `rank_only`, MediaMill, `joint`, 0,75. Публикуются средняя парная разность macro-F1, число выигрышей/равенств/проигрышей, сохранённая доля исходного качества и число моделей, прошедших ограничения. Остальные правила, лимиты и датасеты — вторичные проверки механизма и чувствительности, а не повод задним числом менять основной результат.

Обнадёживающий результат основного сравнения: положительная средняя парная разность macro-F1, не меньше трёх выигрышей из пяти и не меньше прошедших ограничения моделей, чем у контроля. Невыполнение не опровергает все схемы $AB^\top+S$: проверены три фиксированных правила, небольшой набор рангов и пересекающиеся разбиения. По этим пяти разбиениям не рассчитывается формальная значимость как по независимым выборкам.

Остановка: один законченный сравнительный запуск, затем обсуждение с пользователем; максимальная длительность — час. Не менять команду, окружение или замороженного родителя. Правила `orx` ограничивают исправления узла, не давшего ответа, двумя последовательными неудачными запусками.
