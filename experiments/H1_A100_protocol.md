# H1. Запас сокращения модели на A100

Статус: разведочная проверка. Это не подтверждение адаптивного контроллера, регуляризации скетчингом или пользы RMT.

## Вопрос

Можно ли уменьшить число коэффициентов готовой модели хотя бы на 25%, сохранив ошибку на независимой тестовой выборке в пределах 1%, 2% или 5% относительно базовой модели, выбранной по проверочной выборке?

25% — заранее заданный ориентир для разведочной серии, а не утверждение о достигнутом эффекте. Результаты всех трёх допусков сохраняются независимо от успеха по основному допуску 5%.

## Зафиксированная сетка

- Helena: 12 000 объектов, 27 признаков, 100 классов; фиксированная стратифицированная подвыборка.
- MediaMill: 12 000 объектов, 120 признаков, 101 метка; фиксированная подвыборка исходного представления LIBSVM.
- Yeast: полный OpenML 40597, 2 417 объектов, 103 признака, 14 меток.
- Пять повторов: 404, 414, 424, 434, 444. В каждом повторе одинаковые разбиения и начальные значения модели для всех вариантов.
- Три глубины: 3, 5, 7; два значения lambda_l2: 1 и 10; lr=0.1, max_bin=128, min_data_in_leaf=10.
- Два метода: полный GradientBoosting и SketchBoost с Top-K по норме градиента, половиной выходов и use_hess=True. Это один конкретный вариант SketchBoost, а не проверка всех способов скетчинга.
- 200 деревьев без встроенной ранней остановки; проверяем префиксы 10, 20, 40, 60, 100, 150, 200. Префиксы дают офлайн-оценку выбора размера ансамбля, но не являются новым адаптивным алгоритмом.
- Всего 180 обучений и 1 260 кандидатных префиксов. Префиксы одного обучения не считаются независимыми повторами.

## Выбор и измерения

Разбиения 60/20/20: обучение, проверочная выборка, тест. Для многометочных задач используется итеративная стратификация. Конкретные индексы сохраняются. Встроенная оценка качества получает только проверочную выборку.

Основная ошибка: средняя кросс-энтропия для многоклассовой задачи и средняя бинарная кросс-энтропия для многометочной. Дополнительно сохраняются взвешенная и макроусреднённая F1 с фиксированным порогом 0.5 для меток. Относительный допуск применяется к ошибке, а не к F1.

Py-Boost ограничивает каждую компоненту softmax снизу значением 1e-6; поэтому сумма выходных вероятностей может немного превышать единицу. Перед расчётом многоклассовой ошибки строки нормируются, но только если отклонение массы не превышает числа выходов × 1e-6 плюс 1e-6 на погрешность float32. Большие отклонения, нечисловые значения и выходы вне [0, 1] считаются ошибкой. Правило одинаково для обоих методов и не меняет обучение.

Для каждого повтора эталон — кандидат с минимальной проверочной ошибкой. Компактный кандидат — модель с минимальным числом параметров среди проходящих заданный проверочный допуск. Тестовая ошибка не передаётся функции выбора. Выбор проводится отдельно внутри полного метода, внутри SketchBoost и в объединённой сетке; эти результаты нельзя подменять друг другом.

Параметры: достижимые коэффициенты листьев плюс base_score. Число узлов разбиений, листьев, физических деревьев, выделенных ячеек листьев и объём массивов предсказания сохраняются отдельно. Служебный узел дерева без разбиений не считается настоящим разбиением. Объём массивов не равен размеру сериализованного файла модели.

Сохраняется полное время обучения 200 деревьев. Его нельзя приписывать времени обучения каждого префикса. Для каждого префикса измеряется время предсказания: один прогрев и три повтора на тестовых признаках без использования тестовых меток для настройки.

## Условия интерпретации

Совместный успех одного повтора: сокращение параметров не менее 25% и тестовая ошибка в пределах выбранного допуска. Для первичного положительного сигнала смотрим на не менее четырёх успешных повторов из пяти на отдельном датасете; отсутствие эффекта на другом датасете не отменяет область применения.

Эта небольшая сетка не даёт основания заявлять превосходство над полностью настроенными CatBoost/XGBoost или над всеми вариантами SketchBoost. Если запас найден уже обычным ограничением сложности, это подтверждает возможность компактности, но не новизну HASBoost. Повторные разбиения одного источника не являются независимыми новыми датасетами; дальнейшее подтверждение требует расширения данных и настройки базовых методов.

Никакие новые пороги и гиперпараметры не подбираются по тестовым результатам этой серии. Перед H2 обсуждаем итог H1. MoA исключён.

## Выполнение

Команда всего дерева: /root/hasboost_compactness_20260928/venv/bin/python -u experiments/a100_runner.py. Различия узлов задаются только зафиксированной конфигурацией. Все обучения запускаются через orx exp run с SSH-бэкендом и псевдонимом hasboost-a100.

Версии Python, всех пакетов, GPU и драйвера проверяются по неизменяемому environment.json. Контрольные суммы подготовленных датасетов зафиксированы в a100_data_manifest.json. Ключ доступа не входит в репозиторий и не отправляется на сервер.
