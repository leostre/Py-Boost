# Качество при одинаковом фактическом бюджете коэффициентов

## Вопрос

Узел `5718c774-048e-4d73-bb18-361ecc1560e9`, родитель `bafc9369-60c5-413e-bf9a-61bc244f3bda`. Родитель показал воспроизводимое улучшение прогноза на MNIST, но исправленный контроллер расходовал больше коэффициентов. Теперь проверяем: даёт ли поправка `deceleration` лучшее качество, чем `history`, при практически одинаковом фактическом числе коэффициентов? Постоянная глубина и чередование нужны как дополнительные проверки пользы адаптации.

Протокол фиксируется до новых обучений. Старые узлы, формулы прогноза и их результаты не изменяются. RMT, CatBoost/XGBoost, MoA и отказ от полной калибровочной модели в этот этап не входят.

## Выравнивание размера

На каждом разбиении сначала обучается полная модель: 200 деревьев, глубина 5, скорость обучения 0.1, lambda 1. Число коэффициентов P_ref включает достижимые листья и начальный прогноз. Для K выходов общий предел четырёх ограниченных моделей:

$$B=K\left\lfloor\frac{0.75P_{ref}}{K}\right\rfloor.$$

Ограниченные модели: `fixed`, `alternating`, `history`, `deceleration`. Все заполняют этот предел; достижение целевого качества не останавливает обучение. Проверки качества и причинные решения остаются. Обязательные начальные пробы прежнего планировщика сохраняются независимо от дефицита: после дерева 60 запрашивается глубина 3, после дерева 80 — глубина 5. Начиная с проверки после дерева 100 при нулевом дефиците адаптивный контроллер сохраняет текущую глубину; причина в журнале — `target_met_budget_continuation`. Повторное ухудшение снова включает прежние правила выбора. Первые 60 деревьев имеют глубину 5, проверки идут каждые 20 деревьев. Окна с уменьшенной глубиной из-за остатка бюджета не используются для оценки скорости.

Общий предельный горизонт — 500 деревьев, включая начальные 60. Полная модель остаётся на 200. Это новый контролируемый режим: увеличение горизонта меняет оценку оставшегося числа деревьев, отключение остановки меняет траектории. Это не точное повторение родительских моделей. Стоимость минимально разрешённого дерева ограничена сверху 2K. Финальная модель считается сопоставимой, если остановилась по бюджету и 0 <= B-P < 2K. Разбиение включается в основное сравнение, только если условие выполнено для всех четырёх вариантов. Разброс их размеров должен быть меньше 2K. У всех одинаковый B; бюджет учитывает начальный прогноз, а не только новые листья.

Не достигшие нужного размера модели сохраняются и отмечаются как несопоставимые. Их нельзя автоматически считать проигрышем по качеству или исключать без указания. Порог сопоставимости не меняется после результатов. До ограниченных обучений проверяется, что бюджет допускает общий начальный участок полной модели с запасом на дерево глубины 5. Нарушение — ошибка подготовки, а не ответ на гипотезу.

## Серия и ресурсы

- MediaMill и Yeast: разбиения 704, 714, 724, 734, 744; MNIST: 904, 914, 924, 934, 944. Все отличны от предыдущего этапа. Тот же источник данных и те же контрольные суммы.
- 3 набора × 5 разбиений × 5 вариантов = 75 основных обучений. Дополнительно 8 небольших GPU-проверок четырёх контроллеров на двух типах задачи.
- Разбиения 60/20/20 сохраняются. История G/H: 512 фиксированных обучающих строк, снимки каждые 20 деревьев; только диагностика, не RMT-контроль.
- Только существующая A100 через `orx exp run --backend ssh --host hasboost-a100`, неизменные команда и окружение. Не более 3 часов новых вычислений. Не запускать дополнительные основные серии и не переходить к следующей гипотезе без обсуждения.
- Валидация управляет глубиной. Тест оценивается один раз у окончательной модели; промежуточные тестовые показатели не вычисляются. Нельзя выбирать префикс по тесту.

## Заранее заданные критерии

Основной набор — MNIST: именно там у родителя воспроизведено улучшение прогноза. MediaMill и Yeast проверяют переносимость. Для каждого набора и каждого контроля (`history`, `fixed`, `alternating`) отдельно считаем парные отношения окончательных показателей `deceleration` / контроль.

Преимущество по качеству при сопоставимом размере требует всех пяти сопоставимых разбиений, уменьшения тестовой CE хотя бы в 4 из 5 пар, медианного отношения тестовой CE <= 0.99 и медианного отношения валидационной CE <= 1.00. В каждой из пяти пар оба тестовых F1 должны быть не ниже 0.99 значения контроля. При нулевом F1 контроля ограничение для этого показателя пустое. Это описательный критерий, не утверждение статистической значимости.

Практическая пригодность для исходной задачи требует дополнительно не менее 4 из 5 моделей, одновременно прошедших допуски полной модели на валидации и тесте, и не меньше таких моделей, чем у контроля. Допуски: CE <= 1.05 CE_ref, macro-F1 и weighted-F1 >= 0.95 соответствующего F1_ref. Результат по CE и результат по всем допускам указываются отдельно.

Польза поправки требует преимущества над `history`; польза адаптации — также над `alternating` и `fixed`. Одинаковый размер не является выигрышем по размеру. Разное число деревьев, время и затраты калибровки показываются отдельно: качество при одинаковых коэффициентах не доказывает одинаковые вычисления или одинаковое число шагов оптимизации. Пять разбиений одной выборки могут пересекаться; не считать окна независимыми наблюдениями и не заявлять универсальное превосходство.

Отрицательный результат ограничивается данным правилом распределения, пределом 75%, наборами и горизонтом. Отсутствие активации поправки не является её опровержением. После проверки — отчёт, замораживание узла и обсуждение следующего этапа.
